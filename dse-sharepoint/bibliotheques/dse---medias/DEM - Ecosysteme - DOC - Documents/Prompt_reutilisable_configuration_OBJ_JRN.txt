MISSION

Configurer uniquement la liste SharePoint existante OBJ-JRN. Ne modifier aucune autre liste. Ne créer aucune ligne, aucun journal et aucune donnée.

OBJECTIF

OBJ-JRN doit devenir le journal central DSE pour les créations, modifications, suppressions logiques, validations, contrôles, anomalies, verrouillages, déverrouillages, imports, exports, actions IA et actions utilisateur.

CONTROLES PREALABLES

Vérifier l’existence et le schéma de :
- OBJ avec ID-OBJ ;
- OBJ-ACT avec ID-ACT ;
- OBJ-REL avec ID-REL ;
- OBJ-JRN.
Vérifier que OBJ-JRN est vide avant configuration.

COLONNES

- ID-JRN : Texte, obligatoire, unique, indexé. Réutiliser de préférence la colonne native Title en la renommant ; ne pas créer de doublon.
- OBJ : Lookup vers OBJ.ID-OBJ, indexé.
- ID-ACT : Lookup vers OBJ-ACT.ID-ACT, indexé.
- ID-REL : Lookup vers OBJ-REL.ID-REL, indexé.
- DATE-EVENEMENT : Date et heure, obligatoire, indexée.
- TYPE-EVENEMENT : Choix obligatoire et indexé : CREATION ; MODIFICATION ; SUPPRESSION_LOGIQUE ; VALIDATION ; CONTROLE ; ANOMALIE ; VERROUILLAGE ; DEVERROUILLAGE ; IMPORT ; EXPORT ; IA ; UTILISATEUR.
- ACTION : Texte.
- ANCIENNE-VALEUR : Texte multilignes, texte brut.
- NOUVELLE-VALEUR : Texte multilignes, texte brut.
- ACTEUR : Personne ou Groupe, une seule valeur ; autoriser personnes et groupes si l’API le permet.
- SOURCE : Choix : MANUEL ; IMPORT ; APPLICATION ; IA ; WORKFLOW ; SYSTEME.
- RESULTAT : Choix indexé : SUCCES ; ECHEC ; AVERTISSEMENT.
- ANOMALIE-DETECTEE : Oui/Non, défaut Non.
- CONTROLE-PASC-ARA : Oui/Non, défaut Non.
- VERROUILLE : Oui/Non, défaut Non.
- NOTES : Texte multilignes, texte brut.

METHODE ROBUSTE

Pour une liste existante :
1. Créer d’abord les nouvelles colonnes sans editSchemaXml d’indexation.
2. Relire le schéma.
3. Renommer/configurer la colonne native Title en ID-JRN.
4. Appliquer les index seulement après confirmation de l’existence des colonnes.
5. Après chaque échec, relire le schéma car certaines opérations SharePoint peuvent avoir été appliquées partiellement malgré un résultat d’échec.
6. Ne jamais créer une seconde colonne ID-JRN si Title est déjà correctement configurée.
7. Ne pas supprimer ou recréer OBJ-JRN sans autorisation explicite.

CONTROLE APRES CONFIGURATION

Vérifier explicitement :
- les 16 colonnes métier ;
- les cibles et champs d’affichage des 3 lookups ;
- ID-JRN obligatoire, unique et indexé ;
- DATE-EVENEMENT obligatoire et au format Date et heure ;
- TYPE-EVENEMENT obligatoire avec les 12 valeurs exactes ;
- SOURCE et RESULTAT avec leurs valeurs exactes ;
- les trois valeurs par défaut Non ;
- les 7 index ;
- l’absence de lignes.
Documenter toute colonne technique résiduelle ou limitation d’API.

ANALYSE IA SHAREPOINT SANS MODIFICATION

- analyser la structure ;
- identifier les risques ;
- proposer les colonnes manquantes ;
- vérifier la compatibilité avec OBJ, OBJ-ACT et OBJ-REL ;
- évaluer la compatibilité avec le futur pilote Application DemainSite ;
- ne créer aucune automatisation, donnée ou autre modification.

RAPPORT OBLIGATOIRE

Créer Rapport_configuration_OBJ_JRN.txt même en cas d’échec, avec :
- Date ;
- Colonnes créées ;
- Lookups créés ;
- Index créés et non appliqués ;
- Contraintes appliquées ;
- Compatibilité OBJ ;
- Compatibilité OBJ-ACT ;
- Compatibilité OBJ-REL ;
- Compatibilité pilote DemainSite ;
- Conseils IA SharePoint ;
- Limitations détectées ;
- Erreurs rencontrées ;
- Résultat final.

Créer aussi Prompt_reutilisable_configuration_OBJ_JRN.txt et proposer les deux fichiers en téléchargement.
